# ADR-0004: Published хранит только актуальную сцену

Статус: принято.

Дата: 2026-08-31.

## Контекст

Продукту нужна безопасная кнопка Apply, но не интерфейс истории опубликованных версий. Текущая запись settings, Draft и Published одной последовательностью создаёт ненужную связанность.

## Решение

- `published.scene.json` содержит одну актуальную Scene.
- Apply не сохраняет settings и не обязан пересохранять Draft.
- Новая Scene полностью валидируется и сериализуется до atomic replace Published.
- WS `configChanged` отправляется только после успешного replace.
- Automatic safety backup разрешён для recovery и не является пользовательской историей.

## Последствия

- Простая модель для пользователя и runtime.
- Нет встроенного возврата к произвольной прошлой публикации.
- Recovery хранит ограниченное количество технических backup по retention policy.

## Отклонённые варианты

- Immutable Published history — лишняя сложность для текущего продукта.
- Общая транзакция settings + Draft + Published — смешивает независимые данные.
- Сначала WS, потом запись — OBS может запросить ещё не существующую revision.

## Проверка

- Fault injection до replace сохраняет старый Published byte-for-byte.
- Failed validation не меняет Published и не отправляет событие.
- После успеха endpoint и WS сообщают одну revision/hash.
