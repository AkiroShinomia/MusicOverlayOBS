# ADR-0001: SceneDocument — единственное состояние композиции

Статус: принято.

Дата: 2026-08-31.

## Контекст

Редактор получает и сохраняет Scene v2, но внутри использует `currentConfig.layout`. Постоянные преобразования в обе стороны создают потерю полей, special-ID логику и необходимость дублировать новые функции.

## Решение

- SceneDocument является единственным состоянием композиции в editor memory, Draft, themes, Preview и Published.
- Editor-only state хранится отдельно.
- Legacy config конвертируется один раз при импорте и больше не участвует в обычном цикле редактирования.
- UI изменяет Scene через единый facade; прямые мутации запрещены.
- Shared Renderer получает immutable Scene snapshot.

## Последствия

Положительные:

- одно поле имеет одно место хранения;
- round-trip становится проверяемым;
- Preview и OBS проще сравнивать;
- новые компоненты не требуют расширять legacy layout.

Отрицательные:

- Stage 2F является сложной миграцией;
- до его завершения нужен временный adapter;
- все существующие UI-операции придётся перевести на Scene selectors/mutations.

## Отклонённые варианты

- Долгосрочно поддерживать две модели — слишком высокий риск потери данных.
- Сразу создать Scene v3 — не даёт продуктовой ценности и увеличивает миграционный объём.
- Оставить DOM источником позиции — ломает undo, сохранение и Preview/OBS parity.

## Проверка

- Поиск не находит runtime-использования `currentConfig.layout` после Stage 2F.
- Round-trip fixture сохраняет все известные поля и extensions.
- Inspector, Canvas и Timeline изменяют один Store и дают одинаковый undo/result.
