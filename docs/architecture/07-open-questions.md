# Открытые продуктовые вопросы

Технические решения принимает архитектор. Здесь остаются только вопросы, где ответ меняет то, что видит или ожидает пользователь.

Ни один вопрос ниже не блокирует Gate 0 или Stage 2E.

## OQ-01 — анимированные изображения

Нужно ли пользователю добавлять в overlay анимированные GIF/WebP, или в 2.1 достаточно обычных PNG/JPEG/WebP?

Почему это важно: анимация влияет на размер файлов, управление временем и одинаковое отображение в Preview/OBS.

Рекомендуемое решение для 2.1: только статичные изображения. Анимированные assets добавить позднее отдельным типом компонента.

Решить до: Stage 5.

## OQ-02 — удаление группы

Что должно происходить при Delete на группе с объектами?

Рекомендуемое поведение:

- обычный Delete предлагает удалить группу вместе со всем содержимым;
- отдельная команда `Разгруппировать` сохраняет объекты и их положение;
- действие можно отменить через Undo.

Решить до: Stage 3.

## OQ-03 — реальные данные в Preview

Должен ли Preview по умолчанию автоматически показывать реальную текущую музыку, либо открываться на стабильных тестовых данных?

Рекомендуемое поведение: Preview открывается в последнем выбранном режиме; явный переключатель `Тестовые / Реальные данные`; реальные данные обновляются автоматически без отдельного технического переключателя «WebSocket».

Решить до: Stage 7. До него сохраняется текущее поведение.

## OQ-04 — пользовательский размер холста

Нужно ли в UI 2.1 позволять создавать холст не только 1920×1080?

Рекомендуемое поведение: renderer поддерживает произвольный размер уже в 2.1, но UI предлагает готовые presets и по умолчанию 1920×1080. Ручной ввод ширины/высоты можно включить без изменения архитектуры.

Решить до: Stage 3.

## OQ-05 — дублирующиеся имена тем

Можно ли сохранить две пользовательские темы с одинаковым отображаемым именем?

Рекомендуемое поведение: технические ID всегда уникальны, одинаковые имена разрешены, но UI при сохранении предлагает понятный суффикс `Копия` и дату изменения.

Решить до: Stage 5.

## OQ-06 — момент сброса Timeline

Текущая концепция предполагает, что начало новой песни перезапускает Timeline композиции.

Нужно подтвердить: pause/resume продолжает текущее время, seek песни меняет только progress-компонент, а смена track/session ID запускает Timeline с нуля.

Рекомендуемое решение: именно это поведение.

Решить до: Stage 4.

## Решённые вопросы

### RQ-01 — расположение исходников

Решение: `Project/` не становится отдельным Git-root. Источник истины — общий репозиторий.

### RQ-02 — X/Y

Решение: для пользователя это положение объекта. Для совместимости в данных — координата левого верхнего угла относительно родителя.

### RQ-03 — темы

Решение по результатам продуктового контекста основного чата: тема является полной самостоятельной композицией, которую можно изменить и сохранить как пользовательскую копию.

### RQ-04 — Published history

Решение: хранится только актуальный Published. Safety backup допускается, пользовательская история версий не требуется.

### RQ-05 — settings и Apply

Решение: settings сохраняются отдельно; Apply атомарно заменяет только Published Scene.

### RQ-06 — compositionRef

Решение: функция означает «вставить целую одну композицию внутрь другой». Пользовательского запроса на неё сейчас нет, поэтому в 2.1 она не реализуется и не показывается в UI.

### RQ-07 — OBS и web compatibility

Решение: OBS действительно загружает страницу, но исполняет её своим встроенным браузером. Пользователь не выбирает технологию; команда сохраняет консервативную совместимость и проверяет overlay в поддерживаемом OBS перед релизом.
